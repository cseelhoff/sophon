# Claude Session Context - Sophon Project

## Project Overview
**Sophon** is a production-ready homelab IaC project deploying infrastructure on Proxmox:
- Fedora CoreOS VMs with Podman/Portainer
- Quick start one-liner deployment (DHCP mode, API-only)
- Optional air-gapped mode (HTTP file server transfers container images)
- Services: CoreDNS, Traefik, Nexus, OpenLDAP, Keycloak, Gitea, Nextcloud, Guacamole, n8n, Homepage
- SSO integration via Keycloak OIDC
- Dual backup strategy: docker-volume-backup + Kopia

## Quick Start

```bash
ansible-playbook -i localhost, ansible/site.yml \
  -e proxmox_api_host=pve.example.com \
  -e domain_name=homelab.local
```

## Key Decisions Made
- **Target**: Proxmox (not VMware)
- **CI/CD**: Gitea Actions (not AWX) - simpler, git-centric
- **Backup strategy**: Config backups (text/git) vs Operational backups (binary/volume)
- **SSO**: Keycloak OIDC for all services
- **Reference**: ansible-nas cloned to ./ansible-nas for patterns
- **Quick start**: DHCP mode, API-only, graceful failure with SSH instructions for air-gapped Proxmox

## Backup Strategy Summary
- **Config backups** (git): Ansible playbooks, OPNSense XML, Traefik YAML, LDAP schemas
- **Operational backups** (volume): Nextcloud files, PostgreSQL, Nexus artifacts
- **Tools**:
  - `backup` role: offen/docker-volume-backup for container volumes → NAS
  - `kopia` role: kopia/kopia for filesystem-level backups → S3/NAS/rclone
- **Role**: `ansible/roles/backup` - automated daily volume backups at 2 AM
- **Role**: `ansible/roles/kopia` - filesystem backups with dedup, encryption, retention
